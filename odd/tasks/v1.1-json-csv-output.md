# v1.1 — JSON/CSV Output Pass Across Modules

Branch: (per-module feature branches)
Delivery strategy: ask-on-risk
Test runner: per module

## Specs

S1 — Flag. Every module gains `--json` (Bash) / `-Json` (PowerShell) and `--csv` (Bash) / `-Csv` (PowerShell) flags (mutually exclusive; error if both given) that switch the primary output to the requested format.

S2 — JSON. A single JSON object (or array where multiple records) printed to stdout, valid per RFC 8259, no ANSI color codes, stable key order matching the module's documented fields.

S3 — CSV. A header line followed by one record line per item, RFC 4180 quoting, no ANSI color codes.

S4 — Human default unchanged. Without --json/--csv, existing human-readable (curlie-inspired) output is unchanged (backward compatible).

S5 — Exit codes unchanged. 0/1/2 contract preserved for all output modes.

S6 — Audit log unchanged. Audit log format unaffected by output mode.

S7 — Tests. Each module's suite gains tests asserting valid JSON/CSV output for representative cases.

S8 — Docs. Each module's SPECS/README updated with the new flags.
