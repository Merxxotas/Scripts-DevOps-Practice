# Repository v2.0.0 — 2026-11-27

This release brings breaking webhook authentication and stricter safety behavior, alongside
machine-readable output, isolated labs and CI improvements across the repository.

## Breaking changes and migration

- **EventOps webhooks:** Set `EVENTOPS_WEBHOOK_SECRET` in the daemon environment and configure
  senders with the same secret. Send `X-Hub-Signature-256: sha256=<HMAC>` using HMAC-SHA256 over
  the raw request body. Unsigned or invalid requests are rejected; the listener refuses to start
  without a secret. Both Python and Go now bind to `127.0.0.1` by default. If remote access is
  necessary, explicitly configure the host and protect it with a firewall or reverse proxy.
  Requests have a 1 MB body limit and a 30-second read timeout; actions time out after 300 seconds.
  Check existing clients and long-running actions before upgrading.
- **Log Cleanup:** Review target paths and retention settings before scheduled runs. Protected
  system subtrees and resolved paths are guarded, zero-day retention is rejected, and deletion
  requires a writable target. Uninspectable files are skipped and an incomplete scan aborts
  before preview or deletion; failures can now return exit code 2 instead of processing files.
- **Git Deployment:** Unless backup is skipped, deployment now requires a successful verified
  backup before fetch or pull. An explicitly supplied repository URL must match `origin`.
  A failed pull triggers a hard reset to the pre-deploy revision by default; review local changes
  and the rollback implications before deployment. `--no-rollback` / `-NoRollback` disables it;
  post-deploy failures do not trigger rollback.
- **Log Rotation:** Protected path and resolved-path checks are stricter. The active log is
  truncated only after its rotated backup is verified; review targets and permissions before use.

See the [EventOps](https://github.com/Merxxotas/Scripts-DevOps-Practice/tree/v2.0.0/11-Scheduling-And-Automation),
[Git Deployment](https://github.com/Merxxotas/Scripts-DevOps-Practice/tree/v2.0.0/9-Automated-Git-Deployment)
and [Log Rotation](https://github.com/Merxxotas/Scripts-DevOps-Practice/tree/v2.0.0/8-Log-Rotation-and-Compression)
module documentation for details.

## Highlights

- Bash and PowerShell script modules 1–4 and 6–10 gained JSON/CSV output with matching shared
  keys. Module 5 already supported it; EventOps is a daemon. The earlier changelog's v1.1 label
  describes this post-v1.0.0 work, not a separately tagged release.
- EventOps verifies chunked request payloads after decoding; oversized bodies return 413 and
  malformed framing is rejected. Action timeouts also terminate the action process tree.
- Deployment verifies backups before mutation, including PowerShell dotfiles, and checks explicit
  origins. Rotation verifies backups before truncation; both have Bash/PowerShell guard fixes.
- Labs were isolated from real databases, services, clusters, processes and deployment targets in
  the affected walkthroughs. Tests were hardened, including scan failure and lab assertions.
- CI gained tighter permissions, timeouts and pinned actions, a Windows PowerShell 5.1 cleanup
  test, and a CPU monitor Stage 2/3 parity gate. Dependencies and CI actions were updated.

## Compatibility and distribution

Review each module's requirements and dry-run behavior before upgrading; stricter safety checks can
reject previously accepted configurations. Optional Disk atime work and older advisories remain
pending; this release is not a claim that all security or audit findings are resolved.

This is a source-only release: GitHub provides source archives for the release tag; no custom
binaries or packages are included.
